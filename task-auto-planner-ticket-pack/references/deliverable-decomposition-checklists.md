# Deliverable Decomposition Checklists

Use this reference only after completing the High-Stakes Task Blueprint from `high-stakes-planning.md`, and only when class-specific decomposition would materially improve the lane graph.

These are planning prompts, not fixed templates. Use the matching section to identify missing gates, parallel lanes, component artifacts, review checks, and packaging needs.

## Decision / Recommendation Package

- Is there a threshold source-sufficiency or posture gate?
- Are the competing positions or options explicit?
- Can source, governing standards, and practical consequences be researched in parallel?
- Does one architecture lane need to choose the recommended disposition before drafting?
- Should review test both support and likely objections?
- Does the final package need a decision report, short recommendation, and supporting appendix?

## Persuasive / Position Paper

- What audience and decision standard controls the position?
- Can factual record, governing standards, counter-positions, and outcomes be split into parallel packets?
- Is a position architecture lane needed before drafting?
- Are companion artifacts needed, such as summary tables, appendices, timelines, or a handoff checklist?
- Should review be skeptical and findings-first rather than style-only?

## Advisory Report / Analysis Report

- What question must the report answer?
- What assumptions, constraints, and source limits must be visible?
- Can background facts, controlling standards, options, risks, and recommendations run in parallel?
- Is a selected-position aggregator needed before drafting?
- Does the final package need an executive summary, detailed analysis, and action checklist?

## Formal Request / Response / Handoff Artifact

- What process or format controls govern the artifact?
- Are required sections, signatures, notifications, attachments, or certification steps known?
- Can facts, standards, requested outcome, and supporting materials be split?
- Should a control gate run before drafting?
- Does the finisher need to assemble a handoff checklist?

## Discovery / Investigation / Source Package

- What source inventory is available, missing, or unreliable?
- Can source extraction, chronology, issue tagging, contradiction review, and gap analysis run in parallel?
- Is there a required artifact registry?
- Does the aggregator need to produce a source matrix before any narrative output?
- Should review check chain-of-support and missing-source risk?

## Agreement / Policy / Process Draft

- What existing template, policy, standard, or business rule controls the draft?
- Can clause/section inventory, risk review, stakeholder requirements, and precedent comparison run in parallel?
- Is a design lane needed to choose the structure before section drafting?
- Should sections draft in parallel from one approved structure?
- Does the final package need a redline, clean draft, change log, and open-issues list?

## Control / Audit / Assessment

- What framework, standard, benchmark, or checklist controls the assessment?
- Can source inventory, control mapping, exceptions, risk scoring, and remediation planning run in parallel?
- Is a findings aggregator needed before report drafting?
- Should review test scoring honesty and source traceability?
- Does the final package need findings, source appendix, and remediation tracker?

## Challenge / Objection / Reconsideration Package

- What prior decision, finding, or output is being challenged?
- Can record review, review standard, error taxonomy, impact, and requested correction run in parallel?
- Is a selector lane needed to choose the strongest issues?
- Should review act as a skeptical decision-maker?
- Does the package need a concise challenge, detailed support, and issue-preservation checklist?

## Process Audit / Workflow Diagnosis

- What workflow, system, or operating process is under review?
- Can runtime/source inventory, actor/tool map, artifact lifecycle, observability, and dead-path analysis run in parallel?
- Are trace validation or sample-run probes required before conclusions?
- Should integration dedupe reconcile overlapping findings?
- Does the final package need a diagram, findings table, and prioritized fixes?

## Template / Form / Reusable Artifact Generation

- What future users or agents will consume the artifact?
- What fields, examples, validation rules, and failure modes must be covered?
- Can schema/field design, usage examples, edge cases, and review criteria run in parallel?
- Should review test a realistic filled example?
- Does the final package need the template, instructions, and a validation checklist?

## Source Extraction / Synthesis Packet

- What source types need extraction?
- Can extraction lanes split by source type, chronology, actor, issue, or source family?
- Is a normalization manifest needed before extraction?
- Should aggregation produce both a synthesis and a traceable source table?
- Does review need to check omissions against the source inventory?
